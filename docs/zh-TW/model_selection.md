# 模型選擇規則

> 語言 : *[English](../model_selection.md)*

本文件訂定每個部署目標的最終模型如何選出。它在自訂架構的搜尋之前、也在對測試集做任何評估之前就已 commit，
因此選擇方式無法配合事後看到的結果調整 (commit 的歷史紀錄就是先後順序)。

## 使用的證據

所有決策只使用 **`v2` 切分的驗證集**。每個被選中的模型，在套用本規則之後才在測試集上評估一次，
此後下列內容都不得更改。

- **準確度**：在決策閾值 0.5 下，被誤判的驗證集樣本數 (8 個標籤中任何一個錯誤即算誤判)。每一次訓練以
  最後 5 個 epoch 的平均值代表；每個候選以 3 個隨機種子 (seed)的平均值代表，且都完整訓練 30 個 epoch、
  保留最後一個 epoch 的模型。
- **效率**：在沒有其他工作的機器上 (NVIDIA GeForce RTX 5060 Ti、6 個實體核心的 AMD Ryzen 5 9600X)
  以 `scripts/benchmark_models.py` 量測：
  - GPU：單張推論延遲的中位數，以及每批 256 張的吞吐量，PyTorch FP32
  - CPU 伺服器：單張推論延遲的中位數，ONNX Runtime，6 個執行緒
  - 邊緣代理：單張推論延遲的中位數，ONNX Runtime，1 個執行緒

## 候選模型

- `reports/experiments/architecture_comparison.md` 中的五個現成架構，各自使用其學習率比較所選出的學習率。
- 搜尋結果中位於帕累托前緣 (驗證集錯誤數對 FLOPs)、並以 3 個 seed 完整重新訓練的自訂精簡版 ResNet。

**最終候選的學習率檢查**：架構比較顯示，開啟資料擴增時，部分架構偏好高於 1e-3 的學習率。因此，凡是依下列
規則會被某個目標選中的候選，若原本不是使用 3e-3，就再以 3e-3 訓練 3 個 seed。保留平均錯誤數較少的學習率；
兩者相差在 4 筆以內時，保留原本的學習率。接著以更新後的數字重新套用下列規則。

## 搜尋的最終候選

*於篩選搜尋 `slim_resnet_v1` (`reports/experiments/slim_resnet_v1.md`)之後、任何確認訓練之前加入。*

搜尋以 15 個 epoch、單一 seed 篩選每個設定。篩選時的錯誤數高於完整訓練的錯誤數，而較長的訓練也可能改變
各設定的排名，因此確認的不只是最好的那一個 trial：

- **最終候選**：位於帕累托前緣、且篩選錯誤數不超過**最佳篩選錯誤數 + 20** 的 trial。這個寬度是刻意的：
  搜尋中超參數相近的重複設定，結果最多相差約 7 筆，而訓練長度的改變又增加了不確定性。在 `slim_resnet_v1`
  中，這條規則選出 trial **15、46、10、29 和 36** (篩選錯誤數分別為 74.7、69.3、61.0、57.3 和 57.0；
  最佳值 57.0，門檻 77.0)。被排除的是 trial 42 和 11 (3.2 和 5.3 MFLOPs，錯誤數 122.0 和 115.7)，
  它們的錯誤數是最佳值的兩倍，這樣的差距不太可能靠較長的訓練補上。
- **設定檔**：以 `scripts/export_trial.py` 產生：沿用每個 trial 的架構、學習率、weight decay 與 warmup，
  搭配基礎實驗完整的 30 個 epoch。
- **證據**：與其他候選相同，各訓練 3 個 seed，並以 `scripts/benchmark_models.py` 量測。

搜尋是針對 15 個 epoch 的訓練調整學習率，而短的訓練偏好較高的學習率。因此，上述最終候選的學習率檢查，
同樣適用於這些模型。

## 資格

候選模型的平均驗證錯誤數若不超過**最佳候選的平均值 + 4**，即符合資格。4 筆是單一 seed 下觀察到的
訓練間雜訊；在這個範圍內，候選模型被視為準確度相同。

## 各部署目標的選擇方式

在符合資格的候選中：

| 目標 | 規則 |
|---|---|
| 雲端 GPU | 單張延遲中位數不超過 5 ms；其中每批 256 張吞吐量最高者 |
| CPU 伺服器 | CPU 伺服器延遲最低者 |
| 邊緣 | 邊緣代理延遲最低者 |

GPU 的兩種模式 (即時的單張請求與批次複查)由同一個模型服務：模式屬於服務層 (動態批次)，而不是模型的性質。
延遲上限確保單張請求模式的反應速度；吞吐量決定批次模式的效率。

**平手**：兩個候選在某目標的速度指標上相差不到 10% 時，優先選擇已被其他目標選中的模型，其次是參數較少者。
不同的模型越少，需要驗證、監控和重新訓練的就越少；三個目標都選同一個模型，是可以接受的結果。

## 選擇結果

*於確認訓練之後、對測試集做任何評估之前加入。*

3 個 seed 的平均驗證錯誤數，未經四捨五入計算 (比較表格只顯示到小數點後一位，不足以判斷下列的差距)：

| 候選 | 驗證錯誤數 | 符合資格 |
|---|---|---|
| EfficientNet-B0 | 42.0667 | 是 (最佳) |
| ShuffleNetV2 1.0x (學習率 3e-3) | 43.0667 | 是 |
| MobileNetV3-Large | 43.9333 | 是 |
| ResNet-18 | 44.0667 | 是 |
| MobileNetV3-Small | 46.2000 | 否 |
| 精簡版 ResNet (trial 29、36、10、46、15) | 48.7333 至 71.6667 | 否 |

資格門檻為 42.0667 + 4 = 46.0667。在四個符合資格的候選中：

- **雲端 GPU**：單張延遲中位數都低於 5 ms；ShuffleNetV2 的每批 256 張吞吐量最高 (每秒 7,336 張；
  其次是 MobileNetV3-Large，4,063 張)。
- **CPU 伺服器**：ShuffleNetV2 (0.82 ms)與 MobileNetV3-Large (0.86 ms)相差不到 10%，屬於平手，
  依規則選擇已被其他目標選中的 ShuffleNetV2。在第一次量測中，ShuffleNetV2 直接勝出 (0.74 對 0.85 ms)。
- **邊緣**：ShuffleNetV2 (1.43 ms；其次是 MobileNetV3-Large，1.86 ms)。

ShuffleNetV2 本來就使用 3e-3 的學習率，因此不適用學習率檢查。
**ShuffleNetV2 1.0x (學習率 3e-3)被選為三個部署目標的模型：**

**敏感度**：這個結果取決於 0.1333 筆的差距：MobileNetV3-Small 以這個差距落在資格門檻外，若它符合資格，
就會在三個目標都被選中 (每秒 11,079 張、0.34 ms 與 0.64 ms)。在計算精確數值之前，兩種可能的結果及其後果
都已事先寫下，因此這個差距無法影響決策。

**本規則的一個缺陷**：學習率檢查只涵蓋會被選中的候選，因此一個因為學習率不合適而被排除的候選，永遠不會
被檢查。MobileNetV3-Small 正是如此：它在 3e-3 的單一 seed 結果是 43.6 筆，比它在 1e-3 的平均少 2.6 筆；
若檢查涵蓋門檻附近的候選，它可能就會符合資格。這個缺陷在此照實報告而不修正，因為在知道修改對誰有利之後
才改變規則，正是本規則要防止的事。

**調整程度不對等**：精簡版 ResNet 經過的調整多於現成架構 (以 50 個篩選 trial 搜尋學習率、weight decay
與 warmup，對比現成架構的三個學習率)。由於沒有任何精簡版 ResNet 符合資格，這在本次選擇中不可能對它們
有利，但比較它們的準確度時仍應考慮這一點。

## 測試評估

*於測試集被用於任何用途之前加入。* 測試集只評估一次，使用 `scripts/evaluate_test.py` 與
`conf/evaluation/final_test.yaml`；若報告已存在，評估腳本會拒絕執行。

1. **模型**：被選中設定的 3 個 seed，皆為只在訓練集上訓練的模型。不以訓練集加驗證集重新訓練：驗證集必須
   維持未被訓練看過的狀態，才能用來調整決策閾值。
2. **閾值**：對每個模型 (每個 seed)的每個類別，在 0.05 到 0.95、間隔 0.05 的範圍中，選擇讓該類別在驗證集
   上 F1 最高的閾值。平手時選擇最接近 0.5 (未調整的預設值)者。
3. **主要結果**：在調整後閾值下的測試集錯誤數 (任何一個標籤錯誤即算)，以 3 個 seed 的平均與標準差呈現。
   另外報告：0.5 預設閾值下的錯誤數 (呈現調整的效果)、完全正確率 (exact match)、macro F1、macro 平均
   精確度 (AP)，以及各類別的精確率、召回率與 F1。
4. **兩種不確定性**：訓練的隨機性，以 seed 之間的標準差表示。測試集的有限大小，以 seed 平均錯誤數的 95%
   bootstrap 信賴區間表示 (對測試樣本重抽樣 2,000 次，固定隨機種子，百分位數法)。
5. **其他所有候選，僅作為透明度報告**：其他九個候選以相同流程、各自預先宣告的學習率評估，並報告被選中的
   設定與每個候選之間的成對差異：在相同的測試集 bootstrap 重抽樣上，seed 平均錯誤數的差距及其 95% 信賴區間。
   這些結果呈現以驗證集為依據的選擇，在未見過的資料上是否成立；**它們不會改變選擇**。
6. **交付物**：被選中設定中 seed 0 的模型，以及它調整後的閾值。交付的 seed 事先指定，而不是挑選表現最好
   的 seed，否則就等於又在雜訊上做了一次選擇。
7. **報告**：結果產生後立即 commit。不理想的結果照實報告，不藉由更改模型、閾值或本規則來修正。
